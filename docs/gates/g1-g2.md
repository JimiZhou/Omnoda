# Omnoda v0.3 — Gate G1 and G2

Branch `feat/omnoda-continuity-v0.3`. Base is `feat/omnoda-seed-v0.2` at `6b2e55e`.

## G1 — untrusted execution

Result: **PASS on this Linux amd64 host. BLOCKED on GitHub-hosted runners until the sandbox job proves a user namespace.**

What changed:

- The system verifier runs the candidate entrypoint on a fixture the process cannot edit. A generated `verifier_test.py` is not executed.
- Builder output is diagnostic. It does not set `VerifyPassed`.
- A package with no trusted contract is stored as `unverified` and cannot be enabled. The only contract in this round is the sensor-log sample.
- Activation checks the content hash before disabling the previous version. A failed activation leaves the previous version enabled.
- `go test ./...` skips tests that need bubblewrap. A host without a backend still asserts fail-closed. The `sandbox` CI job installs bubblewrap and exits with `SANDBOX=BLOCKED` when the user namespace probe fails. That job is not a pass.

Evidence on this host (`linux/amd64`, bubblewrap 0.11.1, probe `bwrap --unshare-all ... /usr/bin/python3` exit 0):

- `go test ./internal/evolver/ ./internal/sandbox/ ./internal/capabilities/registry/ -count=1` PASS.
- Hostile cases covered: host file read, write outside the work directory, network, tight loop, fixture path outside the package, a verifier that always prints success, a candidate that returns the wrong counts, a package edited after verification, activation of an unverified version, and refusal when no backend exists.

Not claimed: macOS, Windows, or ARM hardware. Those platforms have no generated-code backend in this tree. The code refuses. That refusal was not executed on those machines.

## G2 — continuity

Result: **FAIL as a device gate. Linux seed behavior is INTEGRATION VERIFIED. Other devices and a live agent session are BLOCKED.**

INTEGRATION VERIFIED on Linux amd64, clean root `/tmp/omnoda-seed-v03b`, loopback port 18799:

- First start created the administrator. No Codex or Claude process was required.
- `report this computer's system info` finished `succeeded` with summary `linux/amd64`.
- `run omnoda.weather for tomorrow` finished `failed` with `capability_missing`.
- `sing a song about routers` finished `failed` with `unsupported`.
- `delete the workspace logs` created a pending approval bound to that task and did not run a capability.
- Repeating the system-info idempotency key returned HTTP 200, `idempotent: true`, and the original `task_id`. A different body with the same key returned HTTP 409.
- `POST /api/v1/agent/run` with no model returned HTTP 409 `no_model`.
- After a process restart, the conversation, messages, and `omnoda.system-info` capability were still present.
- The seed log did not contain the administrator password.

UNIT VERIFIED:

- Message and task insert share one transaction.
- Concurrent use of one owner and key creates one task.
- A second owner does not receive the first owner's task.
- A legacy task with an empty `owner_id` is not readable by a logged-in user.
- Event sequences stay contiguous under concurrent allocation.
- A late success does not replace `cancelled`. A runner panic records `failed`.
- A restart marks a running task and its open run `uncertain`. A queued task with `side_effect=0` stays queued.

BLOCKED:

- Browser E2E. The checks above are HTTP. Closing a tab was not clicked in a browser. The supervisor test shows the run continues after the caller returns.
- A 120-second browser disconnect. The same supervisor path is unit tested with a shorter wait.
- Linux ARM64, macOS Apple Silicon, and Windows x86_64 devices. No hardware was available. Do not add a host-exec fallback to make those platforms pass.
- A live Codex or Claude Code task. Both CLIs are on PATH (`codex-cli 0.165.0`, Claude Code `2.1.316`). Codex `Start` passes `--ephemeral`. That is a new process, not session resume. No live prompt was sent, so agent continuity is not verified.
- A live model call. No provider key was used. Fixture generation is labeled as a fixture.

G2 is not complete. The open device and agent items stay open.
